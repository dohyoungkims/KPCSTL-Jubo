# Bulletin layout and function verification

Verified on October 24, 2026 (America/Chicago), after the staff-layout and font changes. The complete Node suite passed **64 tests**. This records the tested cases and their limits; it does not promise that arbitrary text will fit a fixed four-page bulletin.

## Field and PDF checks

- **56 editable fields**: 3 sermon, 12 worship, 12 roster, 4 midweek, 4 weekly-section, 10 announcement, 4 question, and 7 offering fields.
- A distinct Korean/English fixture updates every field through the application model and Pages storage API. Reload retains every value and its attributed change record.
- All 56 expected values appear on their expected pages in the saved PDF. Two independent checks verify the text: decoding the saved PDF's embedded Unicode maps/text operators, and MuPDF extraction. The seven offering values produce the exact **$2,831.08** total.
- The fixture produces four US Letter pages and **83 measured text lines**, all inside their padded regions and page bounds, with **no warnings**. All four pages were rendered at 2× resolution and visually inspected.
- Eleven additional cases overload one field at a time, including roster cells, midweek cells, weekly text, preacher, announcement title, and question number. They block export and identify the relevant editor section. Existing print tests also cover oversized worship, announcement bodies/column flow, question bodies, unsupported characters, long unbroken text, and tall/wide glyphs.
- Oversized content receives a blocking warning; it is not silently approved for download. The preview and PDF download use the same generated bytes.

The source staff repair moves the three Youth Group text baselines 8.4 points to the right to align with the other entries. It preserves the wording, embedded glyphs, fonts, and surrounding artwork. The uploaded original remains available as the unchanged comparison reference.

## Fonts

The print assets now include the original complete NanumSquare Regular, Bold, and ExtraBold files. Their existing-character metrics match the source subsets. Empty glyph outlines are excluded from the generated character map. Tests verify visible ink and PDF text roundtrips for less common Korean syllables and normalize decomposed Hangul to NFC.

The worksheet still uses the source KoPubWorld Dotum Bold subset. New characters can use NanumSquare or the bundled fallback, so arbitrary new worksheet text is not guaranteed to match the original KoPub typography exactly. Unsupported characters block export. Complex-script shaping and color emoji are outside the renderer's supported scope. See `frontend/assets/print/FONT-NOTICE.txt` for font details and licenses.

## Function checks and remaining limits

Automated model, Pages-storage, shared-API, and controller tests cover saving/reloading; stale and concurrent edits; failed browser writes; list add/reorder/delete/undo; requests, resolve/reopen, and comments; all six completion states; finalization and stale-review protection; immutable finalized content; new-week preservation/reset; JSON backup contents; and selected-week/pending-edit recovery after reload.

Browser QA entered all 56 fields through actual editor controls and verified all 56 values after reload. It rendered all four PDF-preview canvases; tested long unbroken text in the digital view, blocking PDF overflow warnings, undo, request/comment saving and resolution, all six completion buttons, finalization, clipboard link copying, archive search/month filters, and new-week creation/reload without losing the prior finalized week. The narrow-screen check showed mobile navigation and no horizontal page overflow. The name-entry example is now Park Taejin (박태진 목사).

PDF and JSON download buttons reached their success state, but this automation environment did not return a downloaded file event/path, so actual browser download completion remains unverified. The PDF bytes themselves are verified independently above. Physical iOS/Android devices, clipboard-denial fallback, and preview failure/retry were not exercised. These limits prevent a blanket claim that every device-specific behavior has been tested.

**GitHub Pages saves to each browser only.** It has no connected shared online database, and copying the app link does not share a person's edited bulletin. JSON backup export is available; there is no uploaded-backup restore interface.
